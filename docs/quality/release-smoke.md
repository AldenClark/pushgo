# Apple release smoke

This is a bounded native behavior gate, with separate profiles for iOS, macOS, watchOS and their shared Core. It reuses the production Store, ViewModels/controllers and the existing App-owned XCTest fixtures. No test uses launch/version/fixture-ready alone as a product oracle. The exact selectors are owned by `config/release-smoke.json`; deleting/renaming a selected method blocks before execution.

Run `python3 scripts/release_smoke.py core`, `ios`, `ios-notification`, `macos`, or `watchos`. Add `--check` for source selection only (product NOT_RUN). Each execution creates a fresh `build/quality-results/release-smoke/<profile>-<run>/` with native results, raw log and `summary.json`. Swift Testing emits native JSON events; XCTest retains xcresult. Tests must execute, pass, have zero skips and zero runtime warnings. There are no product retries. First failures remain in their original run directory.

The Core profile selects sixteen existing suites (299 current native tests, under ten seconds after build). This is cheap shared contract coverage, not an excuse to run all platform journeys. Native profiles select 12 iOS, one external Simulator notification, 11 macOS and four watchOS methods. One representative device per platform is sufficient; Android/desktop display policy is at least 720p and no tiny-screen matrix is required.

`Apple Release Smoke` is reusable and manually dispatchable per profile. Tag-push publication through `Apple Release` requires all six profiles before either App Store or DMG publication. macOS CI uses the existing sandboxed ad-hoc XCTest builder, with no production credential import. Existing build/concurrency/signing gates remain necessary. Both workflow runs and individual receipts identify the selected revision; uncommitted local runs explicitly report a dirty source tree.

`Apple Release` also supports a manual signing-acceptance dispatch with `app-store` or `dmg` and a candidate version. It validates the candidate against iOS, macOS and watchOS product versions, then runs only the selected existing signing lane. App Store acceptance uses `fastlane ios store_build` and stops after signed IPA/PKG archive/export validation. DMG acceptance uses `fastlane ios release_dmg`, including Developer ID signing and notarization. The signed artifacts and SHA-256 acceptance receipt are retained as Actions artifacts. The receipt says `publication: NOT_PERFORMED` and `product_acceptance: NOT_CERTIFIED`; it does not certify UI or runtime behavior.

Manual dispatch skips the smoke matrix and cannot run App Store upload, GitHub Release, Sparkle hosting, public verification, or appcast repository-push steps. Those steps require the release gate's verified tag-push output. Tag-push release behavior keeps the full smoke matrix and existing publication sequence.

A pass does not prove installed signed Release behavior, APNs network delivery, NSE execution under real background budgets, physical iPhone/Watch connectivity, macOS Sparkle download/install, or production deployment. # Core-flow reassessment

The initial UI selection mostly used preloaded canonical fixtures. Its passing results protect visible operations, but do not establish the complete registration → subscription → send → receive → notification/open → persistence/ACK flow. Test count is not the coverage unit.

`python3 scripts/release_smoke.py gateway-integration --gateway-binary ../gateway/target/debug/pushgo-gateway` now starts a disposable real loopback Gateway and executes the production Apple HTTP service, ingress coordinator, persistence and target router. It checks registration/provider-route setup, subscription, actual send/pull, durability before ACK, exact title/body/channel, accurate open target, canonical read API, replay without duplicate or unread reset, Store recreation, target-only deletion, entity incremental lifecycle, final queue drainage, and no delivery after unsubscribe. Generated authorization/channel credentials and isolated SQLite are test-owned; no production credentials are needed. The host test does not call Notification Center or claim a native App launch: notification click/read side effects remain covered by the separate iOS native profile, and macOS native UI remains BLOCKED on this host.

The integration profile pins the paired Gateway repository and exact revision in `config/release-smoke.json`; CI checks out and builds that revision with its declared Rust toolchain before execution. The receipt also retains the actual executable SHA-256 and Gateway source identity/dirty state. Update that pin when evaluating another Gateway candidate; a passed pair does not certify arbitrary future server builds. No workflow was dispatched in this task.
